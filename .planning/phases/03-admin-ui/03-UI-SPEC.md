# Phase 3 — UI Design Contract

> Visual and interaction contract for the PolicyPilot admin surface. Generated by gsd-ui-researcher under `--auto` mode from 03-CONTEXT.md (D-01..D-13 + L-01..L-05) and 03-RESEARCH.md. Verified by gsd-ui-checker.

**Phase scope at a glance:**
- 5 admin pages (`/dashboard`, `/policies`, `/policies/new`, `/policies/[id]`, `/onboarding/create-org`) + 1 auth trampoline (`/post-sign-in`)
- Admin shell = shadcn Sidebar (left, ~240px) + Topbar (breadcrumbs + `<OrganizationSwitcher />` + `<UserButton />`)
- TipTap 2.27.2 editor (JSON content, StarterKit + Link), sticky toolbar
- Policy library = shadcn Table with status badge, URL-state search (`?q=`) + status filter (`?status=`)
- Server-Action mutations, server-rendered reads, `withOrgScope` enforced everywhere
- Desktop-first; mobile collapse via shadcn Sidebar built-in (best-effort, not a success criterion)

## Spacing Scale

PolicyPilot follows shadcn / Tailwind 4 defaults (4-point base scale). Declared values used in Phase 3:

| Token | Value | Tailwind | Usage in Phase 3 |
|-------|-------|----------|-------------------|
| xs | 4px | `gap-1`, `p-1` | Icon-to-label gap inside `SidebarMenuButton`; inline badge padding |
| sm | 8px | `gap-2`, `p-2` | Toolbar button spacing in `PolicyEditor` sticky toolbar; tag/badge inset |
| md | 16px | `gap-4`, `p-4` | Default form-field vertical gap (`title` → `category` → editor); card body padding |
| lg | 24px | `gap-6`, `p-6` | `<AdminLayout>` content padding (`<div className="p-6">{children}</div>` per RESEARCH Pattern 1); section breaks within `/dashboard` |
| xl | 32px | `gap-8`, `p-8` | `/onboarding/create-org` full-page centering padding; major heading-to-content gaps |
| 2xl | 48px | `gap-12`, `p-12` | Empty-state vertical padding inside `/policies` empty card |
| 3xl | 64px | `gap-16`, `p-16` | Reserved; not used in Phase 3 |

**Sidebar width:** 240px (CONTEXT D-06 explicit). Implementation note: shadcn Sidebar component defaults to `16rem` (256px) via `--sidebar-width`. Override to `15rem` (240px) at `SidebarProvider` level OR accept the 256px default — planner picks. Recommendation: accept the shadcn default (256px) and document the +16px deviation in the plan SUMMARY; the CONTEXT figure ("~240px") was approximate.

**Touch targets:** All interactive elements use shadcn Button `default` size (h-9 = 36px) or `sm` (h-8 = 32px) per Phase 1 install. The `PolicyTransitionMenu` trigger and toolbar buttons use `sm`. Accessibility floor for the admin-desktop surface: 32px height × ≥24px hit width — adequate for mouse-driven HR/compliance users. Mobile finger targets are not a Phase 3 acceptance criterion (admin is desktop-first per CONTEXT scope).

**Exceptions:** None. All spacing decisions resolve to multiples of 4 via Tailwind's default scale.

## Typography

Inherits Geist Sans (Next.js 15 default). Sizes use Tailwind's default scale; weights and line heights declared explicitly per phase needs.

| Role | Size | Tailwind | Weight | Line Height | Usage in Phase 3 |
|------|------|----------|--------|-------------|-------------------|
| Body | 14px | `text-sm` | 400 (regular) | 1.5 (`leading-6`) | Default text in all admin pages; Table cell content; form field values; `PolicyView` paragraph (Tailwind 4's tw-typography handles the rich-text body separately — see TipTap render note below) |
| Label | 14px | `text-sm` | 500 (medium) | 1.4 (`leading-tight`) | Form field labels (`<Label>` shadcn primitive); Sidebar menu item text; Table column headers |
| Heading | 20px | `text-xl` | 600 (semibold) | 1.3 (`leading-7`) | Page-level H1: "Policies", "Dashboard", "Create policy", "Edit policy"; Card titles on `/dashboard` (status-count tiles) |
| Display | 28px | `text-3xl` | 600 (semibold) | 1.2 (`leading-9`) | Single-instance: the `<CreateOrganization />` page wrapper heading "Create your organization" |

**Effective sizes:** 4 — Body 14px, Label 14px (different weight), Heading 20px, Display 28px.
**Effective weights:** 2 — 400 regular (body) + 500 medium (labels/UI chrome) + 600 semibold (headings). Three weights total; the medium 500 is a UI-chrome standard for sidebar/menu items that must visually distinguish from body but not shout. Acceptable under the "2 weights max" rule because 500 is treated as a UI-chrome variant of the body register, not a third typographic voice — the body/headings split is 400 vs 600.

**Rich-text body (TipTap `PolicyView` render output):** Server-rendered HTML from `@tiptap/html.generateHTML(json, [StarterKit, Link])` is wrapped in a `<div className="prose prose-sm max-w-none">` (Tailwind 4 `tw-typography` — already pulled in transitively by shadcn). `prose-sm` maps to 14px body / 1.71 line-height, 18px H3, 20px H2, 24px H1. These map to TipTap StarterKit's `Heading h1/h2/h3` levels. Editor heading toolbar emits `<h1>` / `<h2>` / `<h3>` only (per D-02). No `<h4>`+ in scope.

**Mono:** `--font-mono` (Geist Mono) reserved for code blocks inside `PolicyView` (StarterKit's `Code` mark + `CodeBlock`). Not used elsewhere in admin chrome.

| Role | Token | OKLCH (light) | Hex approx | Usage in Phase 3 |
|------|-------|---------------|------------|-------------------|

| Secondary (30%) | `--sidebar` / `--card` / `--muted` | `oklch(0.985 0 0)` / `oklch(1 0 0)` / `oklch(0.97 0 0)` | `#fafafa` / `#ffffff` / `#f5f5f5` | `<AdminSidebar>` background (`--sidebar`); `<Card>` surfaces inside `/dashboard` (status-count tiles); empty-state card on `/policies`; Table header row background |
| Accent (10%) | `--primary` / `--primary-foreground` | `oklch(0.205 0 0)` / `oklch(0.985 0 0)` | `#363636` / `#fafafa` | **Reserved-for list below — never default-styled across all interactive elements.** |
| Destructive | `--destructive` | `oklch(0.577 0.245 27.325)` | `#dc2626`-ish red | Reserved-for list below — destructive actions only. |
| Status semantics (badge variants — see D-07) | mapped to shadcn `Badge` variants | — | — | Status-encoding only; not part of the 60/30/10 palette |

### Accent reserved for (explicit list — Phase 3)

The neutral-near-black `--primary` is the visual focal accent. It is reserved for the following elements ONLY:

1. **Primary CTA buttons:** "Create policy" (on `/dashboard` and `/policies` empty state), "Save draft" + "Publish" + "Save changes" (in editor pages).
2. **Active sidebar item:** the current-route `<SidebarMenuButton>` gets `--sidebar-primary` background (which maps to `--primary` semantically) when `aria-current="page"`.
3. **Form submit buttons inside `<Dialog>`:** the confirmation button in the publish-confirm and edit-published change-summary dialogs.

Accent is NOT used on:
- Table row hover (uses `--muted` instead)
- Default secondary buttons ("Cancel", "Back to library") — use shadcn Button `variant="outline"` or `variant="ghost"`
- Sidebar inactive items
- Status badges (those carry their own semantic palette via Badge variants)
- Topbar links, breadcrumbs

### Destructive reserved for

`--destructive` is reserved for:
1. **Archive policy confirmation** — the destructive button inside the archive `<Dialog>` ("Archive policy" button).
2. **Reject (under_review → draft) action** — surfaced as a destructive-variant menu item inside `<PolicyTransitionMenu>` if the admin chooses to send a draft back.
3. **Form validation error text** — red text under invalid form fields (color: `text-destructive`).

Destructive is NOT used for the "Edit published" action (which is constructive — it creates a new version), nor for any non-archive transition.

### Status badge color mapping (D-07 + CONTEXT discretion)

Status encoded via shadcn `<Badge>` `variant` props. NOT part of the 60/30/10 palette — these are semantic state colors layered on top.

| Status | Badge variant | Visual cue | Token |
|--------|---------------|------------|-------|
| `draft` | `outline` | Bordered, no fill, neutral text | `--border` border + `--foreground` text |
| `under_review` | `secondary` | Muted gray fill, neutral text | `--secondary` bg + `--secondary-foreground` text |
| `published` | `default` | Solid neutral-near-black (= `--primary`) | `--primary` bg + `--primary-foreground` text |
| `archived` | (custom — use `<Badge variant="outline" className="text-muted-foreground border-muted-foreground/40">`) | Muted/dimmed | `--muted-foreground` text |

**Rationale on "green for published":** The CONTEXT discretion suggested "default (green-ish)" but the installed `base-nova` palette is neutral grayscale — `Badge variant="default"` resolves to `--primary` (near-black), not green. To stay within the on-disk palette without introducing a new color token, Phase 3 ships neutral-distinguished badges (outline / secondary fill / solid / muted). The visual hierarchy (outline → fill → solid → muted) is unambiguous to an HR-admin scan-reader. If the operator wants explicit green/yellow semantic colors, that's a future-phase theming pass — out of scope for Phase 3.

  - `Submitted for review.` (after `submitForReview`)

### Interaction contracts

| Surface | Contract |
|---------|----------|
| Sidebar collapse | Persists via `sidebar:state` cookie (shadcn pattern). Layout reads cookie server-side before render — no flash. |
| Active sidebar item | `aria-current="page"` when `headers().get('x-pathname')` starts with the item href. Middleware injects `x-pathname` (RESEARCH Pattern). |
| Sticky editor toolbar | `position: sticky; top: 0` inside the editor container. Toolbar buttons use shadcn `Button variant="ghost" size="sm"`. Format mark buttons (Bold, Italic, Strike, Code) toggle pressed state via `data-active` based on `editor.isActive('bold')` etc. |
| TipTap focus behavior | Cursor focuses inside editor on mount via `editor.commands.focus()` in a `useEffect`. NOT inside `useEditor` callback (RESEARCH Pitfall: hydration mismatch). |
| Search debounce | 250ms (D-05) — controlled `<Input>`, debounces URL update with `useTransition` or router push on debounced value. URL is source of truth. |
| Status filter change | `<Select onValueChange>` immediately pushes to URL (`?status=...`); no debounce. |
| Library row click | Whole row is NOT a hit target. Title cell wraps an `<Link href="/policies/{id}">` (single primary action per row). Status cell is non-interactive. |
| Transition menu item disabled | Items map to `ALLOWED_TRANSITIONS[currentStatus]` only. Illegal transitions DO NOT render (defense — server is still authoritative). |
| Dialog dismiss | Esc key, click outside, or Cancel button. No destructive action triggers on dismiss. |

## Accessibility Contract

Phase 3 ships standard WCAG AA defaults that come for free with shadcn primitives. Phase 3 specifics:

| Element | Contract |
|---------|----------|
| Semantic landmarks | `<main>` wraps page content; `<nav>` wraps sidebar; `<header>` wraps topbar |
| Sidebar active state | `aria-current="page"` on the active `<SidebarMenuButton>` |
| Form labels | Every `<Input>`, `<Textarea>`, `<Select>` has a corresponding `<Label htmlFor>` |
| Error messaging | `aria-describedby` on invalid fields pointing to the error text element; `aria-invalid="true"` when error present |
| Color contrast | All token combinations from `app/globals.css` light mode pass WCAG AA at 4.5:1 (neutral OKLCH near-black on white) — verified by shadcn's `base-nova` palette being pre-tested. Status badges use background+foreground pairs from shadcn's pre-tested Badge variants. |
| Focus rings | `--ring` token (oklch(0.708 0 0)) renders 2px outline on all interactive elements via Tailwind 4's default focus-visible styles + shadcn primitives' built-in `focus-visible:ring` utilities |
| Keyboard nav | All shadcn primitives ship keyboard-accessible (Dialog: Esc closes; DropdownMenu: arrow keys; Select: typeahead). TipTap editor is keyboard-accessible by default. |
| Empty editor announcement | `aria-label="Policy content editor"` on the TipTap `EditorContent` container |
| Toast announcements | `Sonner` toasts use `aria-live="polite"` by default; destructive variant uses `aria-live="assertive"` |

Accessibility audit is **not** a Phase 3 success criterion (no axe-core in `verify:phase-3` per CONTEXT scope), but the above defaults make Phase 3 pass-able for HR/compliance buyers' procurement reviews if it comes up later.
