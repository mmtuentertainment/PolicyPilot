## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Clerk text ID passed to UUID column | `getOrgContext()` returned `session.orgId` (Clerk text `org_xxx`) directly to repository queries whose `org_id` column is UUID. All `/dashboard` queries 500'd with Postgres 22P02. Automated tests missed because vitest used mocks and `check-rls.ts` used fixed internal UUIDs, not Clerk session shape. | blocking | Plan 03-G1 added `scripts/check-auth-context.ts` — a real seed-and-rollback integration test against TEST DB with both a positive control AND a negative control that re-injects Clerk text into `ctx.orgId` and asserts 22P02 fires. Wired into both `verify:phase-2` (via `check-data-layer.ts`) AND `verify:phase-3` (via new `check:auth-context` script in package.json). Future regression of this exact bug will fail the gate loudly. |
| Embedded `<SignIn />` redirect not configured | Clerk Account Portal "After sign-in fallback" config (set in Plan 03-00) only governs Clerk's hosted portal — NOT the embedded `<SignIn />` component shipped by Plan 03-11. Default redirect is `/`. Operator hit this during live smoke when sign-in landed on home page instead of `/post-sign-in`. | blocking | Plan 03-G2 added `NEXT_PUBLIC_CLERK_SIGN_IN_FALLBACK_REDIRECT_URL=/post-sign-in` and `NEXT_PUBLIC_CLERK_SIGN_UP_FALLBACK_REDIRECT_URL=/post-sign-in` to `.env.local.example` + documented in `reference/STACK.md`. `scripts/check-foundation.ts` has a 7th check asserting both env vars present and equal to `/post-sign-in`. `pnpm verify:phase-1` fails loudly if a future engineer removes them. |
| Mixed-identity Clerk session chaos | Operator had stale cookies for a second Clerk user (mmtuentertainment / b2iy) from Phase 2 testing days ago. When the live-smoke `<CreateOrganization />` widget submitted, it used the stale identity instead of the new signup (mmtuproperties / JIum). Webhook fired with the wrong user reference, hit SF-W5 race, membership write was lost. | advisory | For live smoke testing: ALWAYS use a fresh incognito window AND clear cookies for both `localhost:3000` and `*.clerk.accounts.dev` before starting. Sign up + sign in + create org all within the SAME tab/session. Do NOT bounce between accounts. The integration test in `check-auth-context.ts` exercises the code path with deterministic IDs, so no future engineer should need to repeat this live-smoke confusion. |
| SF-W5 webhook race silently drops events | When `organizationMembership.created` arrives before its prerequisite `user.created` (or `organization.created` before user), handler returns 409 — but the `clerk_events` row was already inserted (idempotency write happens before dispatch). On retry, D-03b idempotency short-circuit returns 200 without re-attempting the DB write. Event silently lost. | advisory | Documented inline at `app/api/webhooks/clerk/route.ts:235-244`. Phase 7 obligation: either delete `clerk_events` row when returning 409 (so retries re-fire) OR implement explicit pending-membership queue + structured logging + alerts on stuck rows. Not Phase 3's scope. |
